# アクティブモードとパッシブモード

## なぜ 2 つのモードがあるのか

FTP はコマンドとデータで **チャンネル（接続）を 2 本使う**。

- **コマンドチャンネル**（ポート 21）：「このファイルをくれ」「ログインしたい」などの命令を送る
- **データチャンネル**：実際のファイルデータを送受信する

問題は「データチャンネルを誰が誰に向けて開くか」で 2 つのモードに分かれること。

---

## アクティブモード

```
クライアント ──[ポート21 接続]──▶ サーバー     # コマンドチャンネル
クライアント ◀──[ポート20 接続]── サーバー     # データチャンネル（サーバーから接続しに来る）
```

サーバーがクライアントに向けて接続しに行く。

### 問題点

クライアント側にファイアウォールがあると、**外から来る接続をブロック**してしまう。
Docker 環境では NAT（ネットワークアドレス変換）があるため、サーバーがクライアントの本当の IP に届かない。

→ **Docker 環境ではほぼ使えない**

---

## パッシブモード

```
クライアント ──[ポート21 接続]──▶ サーバー     # コマンドチャンネル
クライアント ──[高番号ポート接続]──▶ サーバー  # データチャンネル（クライアントから接続しに行く）
```

クライアントがサーバーに向けて接続しに行く。

### なぜ Docker で必要か

Docker 環境では、クライアント（自分の PC）から見てサーバー（コンテナ）への接続はできる。
しかしコンテナ側から外への接続は NAT の壁があって届かない。

パッシブモードなら **常にクライアントがサーバーに接続しに行く** ので NAT の問題が起きない。

### 高番号ポートの範囲指定

パッシブモードではデータチャンネルに「高番号ポート」を使う。
どの番号を使うかをサーバー側で **範囲指定** する必要がある（そうしないと docker-compose.yml でポートを開けられない）。

```
# vsftpd の設定例
pasv_min_port=21100
pasv_max_port=21110
```

この範囲のポートを docker-compose.yml でも公開する：

```yaml
ports:
  - "21:21"
  - "21100-21110:21100-21110"
```

---

## まとめ

| | アクティブ | パッシブ |
|--|------------|----------|
| データチャンネルを開く側 | サーバー → クライアント | クライアント → サーバー |
| Docker との相性 | 悪い（NAT の壁） | 良い |
| Inception での使用 | NG | OK |
