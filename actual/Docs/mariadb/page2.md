# page2: Docker 構成での MariaDB の役割

## コンテナの中での位置づけ

MariaDB コンテナは、WordPress コンテナから接続されるバックエンドのデータ保存先である。  
ブラウザや Nginx から直接使うのではなく、主に WordPress から利用される。

流れは次のようになる。

1. ブラウザが Nginx にアクセスする
2. Nginx が WordPress に処理を渡す
3. WordPress が MariaDB に接続する
4. MariaDB が必要なデータを返す

## なぜ分離するのか

MariaDB を別コンテナにすることで、次の利点がある。

- 役割ごとに責務を分けられる
- 再構築時の影響範囲を切り分けやすい
- 永続化をデータベース単位で考えられる
- 本番構成に近い設計の考え方を学べる

## 永続化との関係

MariaDB はデータをコンテナの中だけに置くと、コンテナ削除時に失われる。  
そのため、`/var/lib/mysql` のようなデータ領域を volume や bind mount に逃がすことが重要になる。

Inception では、この「コンテナは消えてもデータは残す」という考え方が非常に重要である。
