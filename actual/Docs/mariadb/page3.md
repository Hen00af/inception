# page3: 初期化処理で何を作るべきか

## 初期化の目的

MariaDB コンテナは、初回起動時に WordPress が接続できる状態まで整える必要がある。  
単に MariaDB サーバーが立ち上がるだけでは不十分である。

## 最低限必要なもの

- WordPress 用のデータベース
- WordPress 用のユーザー
- そのユーザーに対する権限
- root パスワードなどの基本設定

典型的には、初期化用 SQL やシェルスクリプトで次のような処理を行う。

1. データベースを作成する
2. ユーザーを作成する
3. 対象データベースへの権限を与える
4. 設定を反映する

## WordPress 側と対応させる項目

WordPress 側では、環境変数や設定ファイルで次の情報を使う。

- データベース名
- ユーザー名
- パスワード
- ホスト名

ここでいうホスト名は、Docker Compose 上では MariaDB コンテナのサービス名になることが多い。  
つまり、`localhost` ではなく `mariadb` のような名前で接続するのが普通である。

## 学習で見るべき点

- 初回起動と 2 回目以降の起動で動きがどう違うか
- データが volume に残っていると初期化が再実行されるか
- WordPress 側の接続情報と MariaDB 側の作成情報が一致しているか
