# page4: 起動確認と単体学習

## 単体で起動する意味

MariaDB を単体で起動できるようにしておくと、問題を切り分けやすい。

例えば次のような確認ができる。

- MariaDB イメージが正しく build できるか
- 初期化スクリプトが動くか
- データディレクトリが作成されるか
- コンテナが落ちずに stay するか

## Makefile での確認

このリポジトリでは、単体起動のために次のターゲットを用意できる。

- `make mariadb-up`

これにより、MariaDB サービスだけを build して起動できる。  
教科書的には、全体起動の前に各サービスを単体確認する流れは非常に有効である。

## 追加で確認したい項目

- `docker compose ps` で起動状態を見る
- `docker logs` で初期化ログを見る
- MariaDB に接続して DB やユーザーが作られているか確認する

## 学習時の観点

MariaDB を見るときは、「起動したか」だけで終わらせないことが重要である。  
次の 3 点を意識すると理解が深まる。

- サービスとして起動しているか
- WordPress から接続できる状態か
- データが再起動後も残るか

ここまで確認できれば、Inception における MariaDB の役割はかなり整理できている。
